How a run is checked

  1. Preview computes the converted checkpoint, its digest, the field-by-field diff and the v2 contributions that are suppressed because v1 already settled those offsets. It writes only the run record.
  2. Commit writes the checkpoint through tmp → fsync → rename, with an optional crash before/after those steps, then verifies that the log prefix replays to exactly the previewed state.
  3. Recover is idempotent: if the swap did not land it reapplies the preview; if it did it reports already_committed; if newer progress exists it refuses.
  4. Independence: the ingester keeps appending while preview/commit/crash run. The worker refuses a v1 checkpoint; the publisher dedupes on (rule, offset, index) so retries never double-count.
